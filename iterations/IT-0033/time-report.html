6. What was changed

  1. Database: new tables proto_vehicle.tickets (linked to the company and to the vehicle in core.assets) and proto_vehicle.ticket_events (history), with 14 invented demo tickets. Migration db/migrations/vehicle/009_tickets.sql, applied to the Neon branch proto/vehicle.
  2. Data layer: typed hooks generated for the new tables (useTickets, useTicketEvents).
  3. Integration: new TicketsBridge component reads through the hooks and passes the data to the ticket page; every page action (create, edit, status, assign, comment, delete) is saved as one database transaction with its history entry. Neon’s exact error text is shown on failure.
  4. Safety: only the signed-in company’s tickets can be changed; new ticket numbers are company-scoped (C1-TKT-1055, shown as TKT-1055) so companies can never overwrite each other’s tickets.
  5. Page: browser storage removed; vehicles in the form now come from the company’s real vehicle list; the signed-in user’s name is recorded on comments and changes.
  6. Checked live: create, comment, status change and delete all reached the database; test data removed afterwards.

7. Issues and blockers

  1. Blocker (decision, 14 min waiting, not counted): the requested schema was core, but the app’s database is the shared branch proto/vehicle, where core changes are not allowed. The admin chose proto_vehicle instead.
