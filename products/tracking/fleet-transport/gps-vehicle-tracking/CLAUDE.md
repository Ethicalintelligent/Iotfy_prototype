# GPS Vehicle Tracking (N004) — rules for this folder

- **Owner:** not assigned yet (ask the core owner)  ·  **Neon branch:** proto/gps_vehicle_tracking  ·  **Migrations:** db/migrations/gps_vehicle_tracking/
- **Kind:** Base
- **Scope:** only files in this folder (and its migrations folder). Shared changes go through the core owner.
- **UI:** only from `@iotify/ui`; check `packages/ui/CATALOGUE.md` first; missing components go to the library, not here. Look and tokens follow `docs/DESIGN_SYSTEM.md` (no raw colours, sizes or weights; products pass hue names).
- **Data:** only through `@iotify/data` hooks; product tables in `proto_gps_vehicle_tracking`, linked to `core`.
- **Rules:** Paid / Possible / Allowed come from `@iotify/core`; never re-implement them here.
- **Public exports** (`index.ts`): `manifest` and `vehicleSpec` (used by the AIS 140 edition and ConstructSafe). The shared vehicle, device and SIM forms were deleted with `forms/` (IT-0025); the Partner Portal's Add Vehicle, Add Device and SIM add/edit/delete are off until new forms are exported here again.
- **Approved design (IT-0012, Nov 2026):** the menu and screens follow the approved GPS Vehicle Tracking design (17 HTML files, `C:UsersEITDesktops`; approved by Rafiq): Dashboard, Grid View, Map View, Tracking, Centralized Tracking, Alerts ("Detailed View"), Manage (8 modules: Vehicle, Device, Operator, SIM Card, User, Alert Configuration, Geo Configuration, Geo Association), Reports (24 reports), Groups, exactly as in `spec.ts` (`plainMenu`, `ownScreensFirst`). Drivers, Maintenance, Trips, Geofences and Commands stay in the code (reachable by URL) but are not in the menu.
- **Rebuild in progress (IT-0025, 24 Nov 2026):** `demo/`, `forms/`, `shared/` and every screen in `screens/` were deleted on request to build the product new; `screens/` is empty and `spec.ts` has no `screens` yet. Until new screens are added, Dashboard, Map View, Alerts and Reports show the built-in screens and the other menu items show "Coming soon". The old code is in git history (commit f313aa8). Four registry tests ("every menu item has a screen", "approved design menu, with its own screens") fail until the new screens exist.
- **Data in use:** schema `proto_vehicle` (migrations `db/migrations/vehicle/001`–`008`, not `gps_vehicle_tracking/`): vehicles `core.assets` + `vehicle_details` (`operator_id`), devices `core.device_units` + `device_details`, SIMs `core.connectivity` + `sim_details`, users `core.users` + `user_profiles`, `operators`, `alert_configs`, `asset_groups` (nested; core keeps the group name on assets and users), `geofences` (zone type, status, limits, time intervals) and `vehicle_geofences` (days, enter/leave alerts, channels). Demo fleet: Sample Company A (sign in as "Company A admin"). A user limited to a group sees its sub-groups' vehicles too (`useFleet`).
- **Product notes:** Live map, trips, geofences, drivers and commands for vehicle fleets. Screens use demo activity (labelled) until devices report. `manifest.ts` holds the id and scene, `spec.ts` the menu, dashboard, tables, reports and alert rules. Add-ons (Fuel N005, Temperature N006, Weight N007, AC N044, Seat belt N045) have no folders: their screens go here, shown only when bought (Step 11). The edition `gps-ais-140-solution-india/` has its own folder and CLAUDE.md.
