The IoTIFY sidebar and top header (standard rail look, like the partner portal; the owner's choice) frame the pages: `DesignPage` adds a style to each loaded page that hides its own sidebar, drawer, top bar and phone bottom bar and sets `--topbar-h` to 0. - **Grid View, new approved design (IT-0037, 25 Nov 2026):** the admin gave a changed Grid View (`Downloads/Grid-View_approved Chnages`: design PDF + standalone HTML) and asked for it **exactly**, including its page controls **in the IoTIFY header row** (status dropdown after the title; filter, sort and grid/list between search and the bell). - **Page height (IT-0037, the admin's rule):** Dashboard and Grid View scroll as one page with a single scrollbar (Dashboard: whole page; Alert Summary shows all rows, no inner scroll; Grid View: only its card area scrolls). - **Conversion to React (IT-0036, 25 Nov 2026, the admin's decision; root `CLAUDE.md` §3a "Provided HTML becomes React"):** every HTML page is rebuilt as React with the same UI; the HTML files were deleted afterwards (IT-0037). Layout: one folder per menu key, `screens/<key>/Screen.tsx` (default export, loaded on demand by `screens/lazy.tsx`, wired in `spec.ts`) plus `screens/<key>/<key>.css`: that page's original stylesheet scoped under `.st-<key>` (generated by `node tools/design-import/scope-css.cjs <page.html> <out.css> st-<key>`, never edited by hand; each page keeps its own copy because the originals differ slightly). Shared: `screens/smart-track/kit.tsx` (the pages' own components with the same markup and class names; `SmartTrackPage scope=` is the required page frame), `icons.ts` (the pages' exact icons, generated; `registerIcons` for page-only ones) and `shell-fit.css` (fits any page into the IoTIFY shell). Data through `@iotify/data`; activity without a table (positions, trips, alerts, telemetry, report figures) is the original's demo generator applied to the Neon vehicles, labelled demo. **All 10 menu pages are React (25 Nov 2026)**; `DesignPage.tsx` (iframe) and `TicketsBridge.tsx` were removed (tickets logic now in `screens/tickets/useTicketData.ts`). Groups: rename/delete also update the group name on `core.assets` and `core.users`. The page frame lays a page out 1280px wide and zooms it to fit beside the sidebar (as the iframe did); `--st-unzoom` converts window px to page px, and Leaflet maps cancel the zoom (`shell-fit.css`). Pop-ups are portaled into `#st-<key>-portal` (some pages need a `<key>.fix.css` because original selectors relied on `<body>`). **Known limits:** Tracking (`screens/tracking/ported/`) was converted from the bundle by script (`any` types, short names; regenerate with the scratch converter, or clean up by hand later). Manage forms save every field (IT-0038, core change request 002): asset status Maintenance and vehicle extras (category details, trailers, dashcam, fuel monitoring) in `core.assets` (`status`, `attributes`); files in `core.documents`; user passwords as a PBKDF2 hash only in `core.users.password_hash` (`screens/manage/modules/password.ts`); all SIM reminders in `core.connectivity.reminders`; alert parameters, per-day slots, date range, buzzer and escalation in `core.rule_settings`, their recipients and geofence SMS/e-mail lists in `core.notification_recipients`; "+ Add" cities/states in `core.lookups`. Fleet manager / supervisor filters are empty because no vehicle has them set. Report/activity/positions are demo (labelled).
- **Track History changes the developer asked for (IT-0041, numbered IT-0039 on dev/irfan; 25 Nov 2026; deviations from the reference, don't flag them):** the History Filter's date choice is the page's own toggle (`td-seg`) with **Today | Yesterday | Last 7 days | Custom** instead of radio buttons; presets show the period as a line, Custom shows **From** and **To** lines (date + time each). A date opens a small calendar inside the filter that closes on the first click (no Clear/Done); days outside the 7-day limit or in the future can't be picked, and To follows From to stay within it. Playback: **1x = real time**, speeds 1x to 128x doubling (the developer's choice; 128x is the old 1x). The vehicle's playback status takes the live map's 5 km/h limit (`MOVING_KMH`), so a trip point at 0 km/h is Idle or Stopped, not Running; the map icon, speedometer and the panel's **time badge** all show that status colour.
- **Ticket Management (IT-0030, 24 Nov 2026, the admin's request):** a 17th page (formerly `screens/pages/Ticket-Management.html`, now React in `screens/tickets/`; the HTML was never committed and was deleted in IT-0037), menu key `tickets` (Administration group, `support` icon). - **Tickets in Neon (IT-0033):** `proto_vehicle.tickets` (company, vehicle `asset_id` → `core.assets`, plate read from `plate_serial`) and `proto_vehicle.ticket_events` (Created, Comment, Status, Assigned, Edited), migration `db/migrations/vehicle/009_tickets.sql`, 14 invented demo tickets for C1. The admin chose `core`, but core is locked on the shared branch `proto/vehicle`, so the admin agreed to `proto_vehicle`. The page never writes SQL: `screens/tickets/useTicketData.ts` (since IT-0036; formerly the iframe bridge `TicketsBridge.tsx`) reads through `@iotify/data` hooks and turns the page's actions (create, edit, status, assign, comment, delete) into one `useSaveBatch` transaction each, with Neon's exact error text sent back. New ticket ids are company-scoped (`C1-TKT-1055`, shown as `TKT-1055`).
- **Support workflow (IT-0034):** rules in `tickets.ts` (unit tests `tickets.test.ts`); `useTicketData.ts` applies them and gives the page ready-made figures, so the page holds no rules. Roles: Company Admin = support team (everything), **fleet roles = requesters** (raise tickets for vehicles in their group and sub-groups, comment, attach, close a resolved ticket, reopen; they see tickets on their vehicles or reported by them). This is a deliberate exception to "fleet roles are view-only" for this page only; support sessions stay view-only. Workflow: Resolve needs a resolution, Reopen needs a reason and restarts the SLA clock (`sla_started_at`). SLA hours, escalation (overdue → one priority up, reassigned, max 3 levels) and auto-close days are per company in `proto_vehicle.ticket_settings`; escalation and auto-close run as "System" while a writer has the page open (no server job yet). Also `ticket_attachments` (≤ 1 MB, stored in the row) and `ticket_notification_reads` (each user's last-seen time for the page's own notification bell; the shell's bell is shared code, so it was not changed). "From Alert" uses demo alerts from `tickets.ts` (labelled): the Alerts page is an original file and is not edited, so tickets cannot be raised from it directly. Migration `db/migrations/vehicle/010_ticket_workflow.sql`. Outside the app the page only says to open it from the app.
- **Data in use since IT-0040 (25 Nov 2026):** vehicles are `gps.tracked_asset` (`code` = plate, `group_id`), devices `gps.device` (the old device details are its own columns; its SIM is `device.sim_card_id`), SIMs `gps.sim_card`, users `gps.app_user`, groups `gps.asset_group`, device models `gps.device_model`. Screens read them through `useFleetAssets / useFleetDevices / useFleetSims / useFleetUsers / useFleetGroups / useFleetModels` (`@iotify/app-kit`, re-exported by `screens/fleet-rows.ts`), which give text ids and the page's field names; saves turn ids back into numbers and new records get their id from `useNextIds`. `vehicle_details`, `vehicle_io`, `vehicle_geofences`, `alert_configs`, `tickets` and the other core tables now point to these gps ids (numbers). The paragraph below describes the tables before IT-0040.
- **Data in use (before IT-0040):** schema `core` since IT-0039 (built by `db/migrations/vehicle/001`–`011`, then merged by `db/migrations/core/007_merge_proto_vehicle.sql`; `core.geofences` and `core.vehicle_details` are shared with core 004_solution_tables): vehicles `core.assets` + `vehicle_details` (`operator_id`), devices `core.device_units` + `device_details`, SIMs `core.connectivity` + `sim_details`, users `core.users` + `user_profiles`, `operators`, `alert_configs`, `asset_groups` (nested; core keeps the group name on assets and users), `geofences` (zone type, status, limits, time intervals) and `vehicle_geofences` (days, enter/leave alerts, channels). Demo fleet: Sample Company A (sign in as "Company A admin"). A user limited to a group sees its sub-groups' vehicles too (`useFleet`).
