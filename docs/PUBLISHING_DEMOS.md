# Publishing demos on claude.ai

> **One application.** The demo file is generated from the same React code by the build, like any
> deployment package. Nobody edits it and it is not stored in Git. The main shared demo is the
> staging server (REFACTOR_PLAN Step 13b); these files are an optional extra for claude.ai links.

`pnpm build:demo` builds each app as **one self-contained HTML file** in `demo/`
(`iotify-admin.html`, `iotify-partner.html`, `iotify-customer.html`). Publish a file as a claude.ai
artifact; viewers connect Neon in claude.ai (Settings › Connectors) and the page reads and writes
through that connector (`VITE_DATA_MODE=claude-mcp`). Addresses inside the page look like `#/apps`.

## Before the first build
Copy `.env.demo.example` to `.env.demo.local` and set each app's **Neon branch** (CORE_RULES rule 6):
- **Admin Console:** may use `main` (leave `VITE_NEON_BRANCH_ADMIN` empty).
- **Partner portal, customer apps:** a branch of their own. The build stops if it is missing or is
  `main`. Use a demo branch, not `test/e2e` (the tests reset that one).

Optionally set `VITE_DEMO_URL_<APP>` to the other apps' published links, so cross-app links
(support sessions, a dealer's customer sign-in pages) open the right demo; then rebuild.

## What the build checks
`tools/demo/collect.js` refuses a file that loads outside scripts or styles, contains anything that
looks like a database password, or isn't using the claude-mcp connection.

## Known limits
- Each app is its own file: signing in to one doesn't sign you in to another.
- The connector's replies carry no column types; the connection turns known number columns
  (`NUMBER_COLUMNS`, generated by `pnpm db:types`) back into numbers.
- Tested with a stand-in connector (`e2e/demo.spec.ts`) using the reply shape Neon's connector
  returned on 20 Nov 2026; check a real published page after connector updates.
